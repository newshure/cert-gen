# codes.md

What / Why / How. AI 우선 포맷 — 코드를 읽기 전에 구조와 의도를 파악하기 위한 색인.

## 전역 원칙

- **What**: 로컬 Root CA 를 보관하면서 leaf 인증서를 발급하고, 이력을 SQLite 로 추적하고,
  필요한 포맷으로 변환하는 **설치 과정 없는 단일 실행 파일**. 프런트엔드는 CLI(정본) + TUI.
- **Why**: `openssl` 명령 조합을 손으로 반복하면 (a) 확장 설정을 틀리고, (b) 무엇을 언제
  발급했는지 추적이 안 되고, (c) nginx/K8s/Java 가 각각 다른 포맷을 요구해 변환이 반복된다.
- **How**: X.509 는 거의 전부 Go 표준 `crypto/x509`. PKCS#12·JKS·CRL 도 직접 쓴다
  (`keytool` 호출 없음). `openssl` 은 **교차 검증에만** 쓰고 없어도 동작한다.
  코어는 프런트엔드 심볼을 import 하지 않는다.

## 설계를 지배하는 제약

1. **앱 인증이 없다** → CA 키 패스프레이즈가 사실상 유일한 서명 권한 통제다. 기본값을
   암호화로 두고, 패스프레이즈를 **argv 로 받지 않는다**(`/proc/<pid>/cmdline` 노출).
   받는 경로는 환경변수·stdin·TTY 프롬프트 셋뿐이다.
2. **CA 출처가 두 가지다** → cert-gen 이 만든 CA(상태 디렉터리 소유)와 외부 디렉터리의 CA
   (복사하지 않고 그 자리에서 사용). 두 경로가 `ca.Material` 하나로 수렴한다.
   외부 CA 도 이력에는 한 번 등록해(`is_external=1`) serial·순번 관리를 같은 경로로 태운다.
3. **설치 과정이 없어야 한다** → `CGO_ENABLED=0` 정적 링크. C 의존이 하나라도 있으면 glibc
   버전에 묶여 RHEL 8 과 Debian 13 을 한 바이너리로 못 덮는다. SQLite 는 순수 Go 구현
   (`modernc.org/sqlite`)을 쓴다. Windows 교차 컴파일도 이 제약에서 나온다.
4. **폐쇄망이다** → 의존성 하나하나가 반입 비용이다. 모든 의존성이 바이너리에 정적으로
   들어가므로 실행 호스트에는 아무것도 반입하지 않는다. 컨테이너 이미지는 `COPY` 하나로
   끝나고 빌드 중 네트워크를 쓰지 않는다.
5. **상태 위치 규칙은 하나여야 한다** → `--data-dir` → `CERT_GEN_DATA_DIR` →
   `<현재 디렉터리>/cert-gen-data`. **찾아 올라가지 않는다.** 규칙이 여럿이면
   "어디에 생겼는지" 를 사용자가 추측해야 한다.

## 계층

```
internal/cli (flag)          internal/tui (Bubble Tea)
        └──────────────┴──────────────┘
                       │  둘 다 코어를 직접 부르되 같은 일을 같은 순서로 한다.
                       │  TUI 는 작업 후 'CLI 등가 명령' 을 함께 보여 준다.
                       ▼
  internal/  store · ca · issue · csr · crl · export · manifests · bundle ·
             backup · verify · keymgmt · trust · keys · names · profiles ·
             certbuild · config · fsops · certerr
```

`service` facade 는 두지 않았다. 프런트엔드가 둘뿐이고 코어 API 가 이미 좁아서, 한 겹을 더
두면 같은 시그니처를 두 번 쓰는 일만 늘었다.

## 모듈

### internal/certerr
- **What**: 오류 계층. `Kind` 가 종료코드를 결정한다.
- **Why**: CLI·TUI 가 같은 문장을 내야 한다. 프런트엔드마다 다르게 보이면 사용자가 같은
  문제를 다른 문제로 오해한다. 스크립트가 원인을 구분할 수 있어야 한다.
- **How**: validation 2 / notfound 4 / conflict 5 / verification 6 / toolmissing 69 /
  state 74 / **keyunlock 77** / config 78. keyunlock 을 따로 둔 이유는 프런트엔드가 그것만
  보고 '재입력' 을 유도할 수 있어야 하기 때문이다.

### internal/config
- **What**: TOML 설정 + `CERT_GEN_<섹션>_<키>` 환경변수 오버라이드, 상태 디렉터리 해석.
- **Why**: 설정에 `data_dir` 를 **두지 않는다.** 설정 파일이 상태 디렉터리 안에 있으므로
  순환이 된다.
- **How**: 모르는 키는 `md.Undecoded()` 로 **거부한다**(오타가 조용히 무시되면 설정했다고
  믿는다). `deploy/config.example.toml` 이 실제로 로드되는지 테스트로 고정한다 —
  예시가 스키마에서 벗어나면 그것을 복사한 사용자가 바로 오류를 만난다(실제로 그랬다).

### internal/fsops
- **What**: 원자적 쓰기, 권한, 해시.
- **Why**: 이 도구의 버그는 파일 권한과 원자적 쓰기에서 나온다.
- **How**: `WriteAtomic` 은 `O_EXCL` 로 임시 파일을 만들고 **권한을 생성 시점에 준다**
  (만든 뒤 chmod 하면 그 사이에 읽힌다). Windows 는 대상이 있으면 Rename 이 실패하므로
  먼저 치운다. `ModeSecret 0600` / `ModePublic 0644` / `ModeDir 0750`.
  Windows 용 분기에서 `Chmod` 는 no-op 이고 `(NTFS ACL)` 을 보고한다.

### internal/store
- **What**: SQLite 스키마·마이그레이션·CRUD. 테이블 `private_key`·`ca`·`certificate`·`audit`.
- **Why**: 테이블 몇 개에 ORM 은 과하다. SQL 을 직접 보는 편이 경합·트랜잭션 경계를 통제하기
  쉽다.
- **How**: WAL, `_txlock=immediate`, `busy_timeout`, `MaxOpenConns(1)`.
  `AllocateSeq` 는 `SELECT`→`UPDATE` 다(`RETURNING` 은 SQLite 3.35+ 전용이라, 구형 sqlite 로
  만든 상태 디렉터리도 열 수 있도록 쓰지 않는다).
  `SetCertStatus` 는 0행 UPDATE 를 **오류로** 돌린다 — 조용히 넘기면 "폐기했다" 고 보고한
  뒤 아무것도 폐기되지 않는다.

### internal/keys
- **What**: 키 생성·로드·직렬화. RSA 2048/3072/4096, EC P-256/P-384, Ed25519.
- **How**: 평문은 표준 `MarshalPKCS8PrivateKey`, 암호화는 `youmark/pkcs8`
  (표준 라이브러리는 암호화 PKCS#8 을 읽지도 쓰지도 못한다). `FromPEM` 은 패스프레이즈
  문제와 그 외를 구분해 돌려준다. `PublicPEM` 은 개인키를 넘겨도 공개키를 뽑아 쓴다 —
  시그니처가 `any` 라서 실수하기 쉽고, 그러면 원인을 짐작하기 어려운 오류가 난다.

### internal/names
- **What**: Subject DN 조립, SAN 파싱·검증.
- **How**: `dns:`/`ip:`/`uri:`/`email:` 접두어 또는 자동 판별. 와일드카드는 RFC 6125 대로
  **좌측 레이블 하나만** 허용한다. **CN 을 SAN 에 자동 포함한다** — CN 만 있는 인증서는
  현대 클라이언트가 거부하므로 그대로 발급하면 쓸 수 없는 것이 나간다. IDNA A-label 변환.

### internal/profiles
- **What**: 발급 프로필 → 확장 세트. `root-ca`/`server`/`client`/`server+client`.
- **Why**: 확장을 한곳에 모아 실수를 구조적으로 막는다.
- **How**: `root-ca` 는 `pathLen: 0`(이 CA 아래에 또 CA 를 둘 수 없다 — 중간 CA 를 만들지
  않는 설계와 일치). EC·Ed25519 키에서는 `keyEncipherment` 를 뺀다(의미가 없어 일부
  검사기가 경고한다). `GetLeaf` 는 CA 프로필을 거부한다.

### internal/certbuild
- **What**: serial 생성, 유효기간 창, 인증서 빌드.
- **How**: serial 은 159비트 난수(RFC 5280 권고). `ValidityWindow` 는 `notBefore` 를 설정값
  만큼 과거로 둔다(시계가 빠른 장비에서 "아직 유효하지 않음" 을 피한다). SKI 는 공개키
  SHA-256 앞 20바이트. CA 자기서명과 leaf 서명이 **같은 경로**를 탄다.

### internal/ca
- **What**: Root CA 생성·가져오기·외부 CA 인식, CA 재료 로드.
- **How**: `CreateRoot` 는 DB 를 먼저 넣어 slug 를 선점하고 파일 쓰기 실패 시 보상 삭제한다.
  등록된 키를 쓰면 **복사하지 않고 참조한다** — 복사하면 패스프레이즈를 제거해도 CA 가 쓰는
  사본은 그대로 남아 두 상태가 갈라진다. `DiscoverInDir` 는 선호 파일명 → 글롭 순으로 찾고
  후보가 0개나 2개 이상이면 거부한다. 키-인증서 짝 검증은 `LoadMaterial` 에서 한다
  (암호화된 키는 discover 시점에 비교할 수 없다).

### internal/keymgmt
- **What**: 개인키를 미리 만들어 두고 CA·발급에서 고르는 흐름(0번 메뉴).
- **Why**: 책임 분리(키를 만드는 사람과 인증서를 받는 사람이 다를 수 있다)와 키 재사용
  (장비가 키 교체를 받지 못해 같은 키로 갱신해야 하는 경우가 실제로 있다).
- **How**: 기본은 **평문**이다 — 서버가 읽을 키를 암호화하면 기동할 때마다 묻는다(CA 키는
  반대로 암호화가 기본). 이름이 파일 경로가 되므로 경로 구분자와 `..` 를 거부한다.
  `Load` 는 파일의 공개키가 DB 기록과 다르면 거부한다(어긋난 채로 쓰면 쌍 토큰이 거짓이 된다).
  쓰이는 키는 삭제를 거부하고 사용처를 알려 준다.
  **쌍 토큰** = 공개키 지문 앞 8자리. 키 목록과 인증서 목록에 같이 보여 눈으로 짝을 맞춘다.

### internal/bundle
- **What**: 발급 결과 zip. `privkey.pem`/`cert.pem`/`chain.pem`/`fullchain.pem`/`ca.crt`/
  `request.csr`/`metadata.json`/`USAGE.txt`.
- **Why**: 개인키·인증서·체인이 흩어지면 어느 키가 어느 인증서의 짝인지 잃어버린다.
- **How**: zip 안 `privkey.pem` 에 **0600 을 심는다**(unzip 이 복원하므로 받는 쪽에서 chmod 를
  잊어도 평문 권한으로 풀리지 않는다). 타임스탬프를 고정해 같은 입력이 같은 sha256 을 낸다.
  멤버 이름의 디렉터리 부분을 버려 `../` 가 섞인 zip 도 밖으로 쓰지 못한다. 선언된 크기를
  믿지 않고 상한을 둔 `io.ReadAll` 로 읽는다. **기존 경로는 거부한다** — 경로에 새 인증서
  id 가 들어가므로 충돌 자체가 이상 신호이고, 덮으면 그 자리 개인키가 복구 불가능하게 사라진다.
  `fullchain` 에 Root 를 넣지 않는다(핸드셰이크마다 쓸데없는 바이트를 보낸다).

### internal/issue
- **What**: leaf 발급·갱신·CSR 서명.
- **How**: 순서가 핵심이다.
  ```
  seq 할당(짧은 tx) → serial → 키 생성·서명(tx 밖) → INSERT·커밋 → 번들 쓰기
                                                          → 실패 시 보상 삭제
  ```
  키 생성을 tx 안에서 하면 RSA-4096 생성 수 초 동안 쓰기 락을 잡아 동시 발급이 전부 막힌다.
  번들을 DB 보다 먼저 쓰면 고아 zip 이 남는다. 지금 순서의 최악은 "행은 있고 zip 은 없다"
  이고 그건 명확한 오류로 알릴 수 있다.
  갱신 기본은 **새 키**다(키 재사용은 유출 대응으로서의 갱신을 무의미하게 만든다). 이전 건은
  `superseded` 로 표시하되 **이미 폐기된 건은 건드리지 않는다**(덮으면 CRL 에서 빠진다).
  CA 가 leaf 보다 먼저 만료되면 발급 시점에 경고한다.

### internal/csr
- **What**: CSR 생성(외부 CA 제출용)과 외부 CSR 해석.
- **Why**: **CSR 의 확장은 믿지 않는다.** CSR 은 요청자가 통제하는 입력이고
  `basicConstraints CA:TRUE` 를 넣어 보내는 것도 막을 수 없다. 그대로 복사하면 leaf 를
  요청한 상대에게 CA 를 발급하는 사고가 된다.
- **How**: 공개키·Subject·SAN 만 꺼내고 확장은 버린다. 다만 **버렸다는 사실을 경고로
  알린다** — 조용히 무시하면 요청자는 자기가 넣은 EKU 가 반영됐다고 믿는다. 서명 검증은
  필수다(안 하면 남의 공개키로 아무 이름의 인증서를 받아 갈 수 있다). 서명 알고리즘은
  지정하지 않고 Go 가 키 종류·곡선에 맞게 고르게 둔다 — 우리가 해시 표를 들고 다니면 그
  표가 틀릴 뿐이다.

### internal/export
- **What**: PEM / DER / PKCS#12 / JKS / 신뢰 저장소 변환. 입력은 발급 이력 또는 외부 파일.
- **Why**: 실무에서 가장 잦은 변환이 "남이 준 PEM 을 p12 로" 다. 이력 기반만 지원하면
  기능이 반쪽이 된다.
- **How**: PKCS#12 는 `go-pkcs12`, JKS 는 `keystore-go` 로 **직접 쓴다**(keytool 호출 없음).
  알고리즘 세대를 `Modern2023` 으로 **명시 고정**한다 — 라이브러리의 `Modern` 별칭은 버전이
  오르면 가리키는 대상이 바뀌도록 설계돼 있어 의존성만 올려도 호환 범위가 조용히 달라진다
  (`Modern2026` 은 Java 26·OpenSSL 3.4 이상이라 폐쇄망 레거시에 못 쓴다).
  p12/JKS 체인에는 Root 를 **포함**한다(그 자체로 신뢰 경로를 완성해야 Java 가 체인을 세운다).
  JKS 는 빈 암호를 거부하고 6자 하한을 강제한다(Java 제약 — 통과시키면 keytool 로 다시
  열지 못하는 파일이 나간다). 외부 파일 경로에서는 키-인증서 짝을 확인한다(짝이 아닌 키로
  만든 키스토어는 파일로는 멀쩡해 보이고 서버를 올릴 때야 실패한다).

### internal/manifests
- **What**: `kubernetes.io/tls` Secret, Ingress, nginx server 블록, NPM 안내.
- **Why**: YAML 라이브러리를 쓰지 않는다. 여기서 나오는 파일은 사람이 저장소에 커밋하고
  나중에 읽는 것이라 **주석과 키 순서가 내용만큼 중요한데**, YAML 덤퍼는 맵을 알파벳 순으로
  재배열하고 주석을 버린다.
- **How**: 대신 인용을 직접 책임진다 — `yes`/`no`/`null` 은 YAML 1.1 에서 불리언이라 인용하지
  않으면 문자열이 아닌 것이 된다. 라벨은 정렬한다(Go 의 맵 순회는 무작위라 정렬하지 않으면
  같은 입력이 실행마다 다른 파일을 내고 diff 가 쓸모없어진다). data 키 순서는
  `tls.crt`→`tls.key`→`ca.crt` 고정, base64 는 64자로 접는다. 개인키 없는 tls Secret 은
  거부한다(만들어 주면 apply 는 성공하고 트래픽이 흐를 때 실패한다).
  검증은 `kubectl apply --dry-run=client` 로 한다.

### internal/verify
- **What**: 항목별 검증 보고서. 유효기간·키 짝·체인·AKI/SKI·호스트명·프로필·폐기·교차 검증.
- **Why**: "검증 실패" 한 줄은 고칠 단서를 주지 않는다.
- **How**: 상태가 pass/fail/warn/**skip** 네 가지다 — 확인하지 못한 것을 통과로 보여 주면
  사용자가 검증됐다고 믿는다(CSR 서명 건은 개인키가 정상적으로 없다).
  **AKI/SKI 검사를 체인 검사 앞에 둔다** — 체인이 실패할 때 원인을 알려 주는 항목이 바로
  이것인데, 뒤에 두고 early return 하면 가장 필요한 순간에 단서가 사라진다.
  체인 검증의 `KeyUsages` 를 비우면 Go 가 ServerAuth 를 요구하므로 client 전용 인증서가
  엉뚱한 이유로 실패한다 → 인증서가 가진 EKU 를 기준으로 본다. 키 강도는 종류별로 본다
  (비트 수만 비교하면 EC P-256 이 전부 약한 키로 잡힌다).
  openssl 교차 검증은 '우리 판단과 openssl 의 판단이 **엇갈렸는지**' 를 본다 — 어느 쪽이
  맞는지 우리가 정하지 않는다. 폐기 확인과 교차 검증은 둘 다 옵트인이다(기본으로 돌리면
  CRL 없는 환경에서 늘 skip 항목이 떠 보고가 시끄러워진다).

### internal/crl
- **What**: 폐기와 CRL 생성.
- **Why**: DB 만 바꾸고 멈추면 "폐기했다" 는 기록만 남고 폐기된 인증서는 계속 통한다.
  그래서 `Revoke` 가 CRL 재생성까지 한 흐름으로 처리한다.
- **How**: `reasonCode 0`(unspecified)은 생략한다(RFC 5280 §5.3.1 — 넣으면 일부 검증기가
  경고한다). `certificateHold`(6)는 사유 목록에서 **제외**했다 — 해제 경로를 만들지 않았으니
  넣으면 되돌릴 수 없는 보류가 된다. 빈 CRL 도 만든다("폐기된 것이 없다" 는 유효한 진술이고,
  검증하는 쪽은 파일이 없는 것과 비어 있는 것을 다르게 취급한다). `cRLSign` 없는 CA 는 거부.
  **CRL 배포 지점(CDP)은 넣지 않는다** — 폐쇄망에 CRL 을 서비스할 HTTP 지점을 전제할 수
  없다. 따라서 CRL 은 검증하는 쪽이 파일을 직접 받아 쓰는 용도다(`ssl_crl` 등).

### internal/trust
- **What**: OS(RHEL·Debian·Windows)·Java·컨테이너·런타임 신뢰 등록 **명령 생성**.
- **Why**: **실행하지 않는다.** 신뢰 저장소 변경은 그 호스트의 보안 경계를 바꾸는 일이고
  거의 항상 root 가 필요하다. 도구가 조용히 해 버리면 무엇이 바뀌었는지도 되돌리는 방법도
  사용자가 모르고, sudo 를 삼켜야 한다. 명령을 보여 주면 읽고, 복사하고, 변경 관리 절차에
  넣을 수 있다.
- **How**: 확인 명령과 되돌리기 명령을 함께 낸다. 실무에서 걸리는 지점을 안내에 박았다 —
  **Java 는 OS 신뢰 저장소를 보지 않는다**(가장 흔한 사고), Debian 은 `.crt` 확장자만 읽는다
  (`.pem` 은 조용히 무시된다), RHEL 은 이미 떠 있는 프로세스에 반영되지 않는다,
  Windows 는 `certutil -addstore Root` 와 경로 백슬래시 변환. 경로는 셸 인용한다(공백이나
  작은따옴표가 든 경로가 실제로 있고, 인용하지 않으면 복사한 명령이 다른 파일을 가리킨다).

### internal/backup
- **What**: 상태 디렉터리 전체의 tar.gz 백업·복원.
- **Why**: **백업 파일은 CA 그 자체다.** 0600 으로 쓰고 그 사실을 경고로 낸다.
- **How**: DB 스냅샷은 파일 복사가 아니라 `VACUUM INTO` 다 — WAL 모드에서 `.sqlite3` 만
  복사하면 `-wal` 에 남은 커밋이 빠져 찢어진 스냅샷이 나온다.
  매니페스트를 아카이브 **첫 항목**으로 두고 파일별 sha256 을 담아 복원 전에 전부 대조한다
  (전개 중에 깨진 것을 발견하면 이미 기존 디렉터리를 치워 둔 상태가 되어 양쪽을 다 잃는다).
  복원 순서: 검증 → 임시 위치에 전개 → 기존 것을 **옆으로 치움**(지우지 않는다) → 제자리로.
  마지막 Rename 이 실패하면 치워 둔 것을 되돌린다. tar 경로 탈출(zip slip)과 심볼릭 링크를
  거부한다(우리가 만들지 않은 아카이브도 읽으므로 선택이 아니다). 더 새로운 스키마는 거부.
  `Inspect` 는 **이미 열린 store 를 받는다** — `store.Open` 은 필요하면 마이그레이션을
  수행하므로, 드라이런이 현재 DB 를 고치는 부수효과를 가지면 "아무것도 바꾸지 않는다" 가
  거짓이 된다.

### internal/cli
- **What**: 명령줄 프런트엔드. CLI 가 정본이다.
- **How**: 표준 `flag` 의 서브커맨드. 비밀값은 환경변수·stdin·TTY 프롬프트로만 받는다.
  **플래그를 앞으로 모은다**(`permute`) — 표준 `flag` 는 첫 비플래그에서 해석을 멈추므로
  `cert verify 1 --hostname x` 의 `--hostname` 이 조용히 무시된다. 조용히 틀리는 쪽이
  오류보다 나쁘다. 값을 받는 플래그와 불리언을 구분해야 한다(`--json 1` 의 1 은 위치 인자).
  표 폭은 동아시아 문자를 2칸으로 센다(한글 CN 이 섞이면 열이 어긋난다).
  DN 플래그는 `--org`/`--ou`/`--country` 로 풀어 썼다 — Go 의 `flag` 는 `-o` 와 `--o` 를
  같은 것으로 보므로 Organization 을 `-o` 로 두면 출력 디렉터리 `-o` 와 충돌해 **그 명령을
  처음 실행하는 순간 panic 한다**(컴파일은 통과한다). 모든 하위 명령의 FlagSet 을 실제로
  만들어 보는 테스트로 이 부류를 빌드 단계에서 잡는다.

### internal/tui
- **What**: 터미널 UI(Bubble Tea). 좌측 메뉴 / 구분선 / 우측 콘텐츠 / 하단 저작권.
- **Why**: TUI 는 편의 계층이고 CLI 가 정본이다. 그래서 각 화면은 작업 후 **같은 일을 하는
  CLI 명령**을 보여 준다 — TUI 로 익힌 절차를 스크립트로 옮길 수 있어야 한다.
  비TTY 에서는 TUI 를 거부하고 CLI 등가 명령을 안내한다.
- **How**:
  - 메뉴 0~6 과 번호를 고정한다. 순서를 바꾸면 손에 익은 번호가 달라진다.
  - **반칸 블록 글리프(`▔▁▊▎█`)를 쓰지 않는다.** 폰트에 따라 `ㅁ` 로 깨지고, 깨지지 않아도
    화면이 어지러워진다. 가는 선 테두리만 쓰고 강조는 배경색으로 한다.
  - 드롭다운은 **스페이스로만** 열린다. 화살표로 열리면 항목 간 이동과 값 변경이 섞여
    실수로 설정이 바뀐다. Enter 로도 열지 않는다 — 폼에서 Enter 는 '다음·실행' 이다.
  - SAN 은 여러 줄 입력이고 **Enter 가 줄바꿈**이다(폼 이동은 Tab). 한 줄 입력은 Enter 를
    제출로 먹는다.
  - 숫자키 바로가기는 **글자 입력을 받지 않을 때만** 동작한다(`CapturesText`). 텍스트 필드에
    포커스가 있으면 숫자는 글자여야 한다. 어디서든 되는 길로 `Alt+0~6` 을 둔다.
  - **콘텐츠를 자른다.** lipgloss 의 `Height()` 는 채우기만 하고 자르지 않아서, 긴 내용은
    그대로 흘러 푸터와 저작권 줄을 밀어낸다. PgUp/PgDn 스크롤과 "n/m줄" 표시를 둔다 —
    조용히 자르면 사용자는 내용이 없다고 믿는다.
  - 푸터 키 안내도 폭에 맞춘다. 80칸에서 넘치면 뒤쪽(전역 키)부터 버리고 `…` 로 표시한다.
  - 작업 성공 시 콘텐츠를 끝으로 보낸다. 방금 실행한 결과를 보려고 스크롤해야 하는 것은
    잘못된 동작이다.
  - 패스프레이즈 모달은 **앱 셸이** 들고 있고 그동안 전역 키조차 가로채지 않는다(Ctrl+C 만
    예외 — 어떤 상태에서도 빠져나올 길은 있어야 한다). 화면마다 구현하면 어떤 화면에서는
    모달 위로 단축키가 새어 나간다.
  - 화면 상태는 유지한다(입력 중이던 폼이 메뉴를 다녀오면 비면 안 된다).

## 배포 (deploy/)

### deploy/build.sh
- **What**: linux/amd64 + windows/amd64 바이너리와 `SHA256SUMS` 생성.
- **How**: `-trimpath -buildid=` 로 재현 가능하게 한다. 깨끗한 트리를 요구한다
  (`ALLOW_DIRTY=1` 로 무시 가능) — Go 가 바이너리에 git 커밋을 새기므로, 더러운 트리에서
  빌드하면 `vcs.modified=true` 가 찍혀 "어느 소스에서 나왔는가" 를 답할 수 없다.
- Windows 만 다르게 처리한다. 버전 리소스(VERSIONINFO)를 넣고 **심볼을 스트립하지 않는다.**
  Go 는 `.rsrc` 섹션이 없는 맨 PE 를 만드는데 정상 소프트웨어는 거의 예외 없이 회사명·
  제품명을 담고 있어서, 없는 것 자체가 백신 휴리스틱 점수를 올린다. 스트립도 분석 방해
  신호로 읽힌다. → `docs/manual/antivirus.md`
- `.syso`(버전 리소스)는 gitignore 한다. 빌드 중에만 만들지만 untracked 로 잡히면 모든
  Windows 릴리스에 `+dirty` 가 찍힌다.

### deploy/container/
- **What**: Dockerfile + build.sh. 바이너리 하나를 `COPY` 하는 것이 전부다.
- **Why**: 설치가 필요 없으므로 컨테이너는 필수가 아니다. 클러스터 안 Job 이나 "호스트에
  바이너리를 두지 않는" 정책용이다.
- **How**: 이미지 빌드 중 네트워크를 쓰지 않는다(컴파일은 호스트에서 끝낸다). `USER certgen`
  (UID 10001)로 돌리고 상태 디렉터리를 `VOLUME` 으로 둔다 — 볼륨 없이 띄우면 컨테이너가
  사라질 때 CA 개인키도 사라진다. 이미지에는 CA 키를 담지 않는다(레지스트리에 CA 가 올라간다).

**셸 함정 두 개**를 겪었다. 둘 다 `set -euo pipefail` 과 겹쳐 **조용히** 죽는다.

| 금지 패턴 | 왜 | 대신 |
|---|---|---|
| `grep -q P f && die ...` | 패턴이 **없는 정상 경우**에 grep 이 1 을 반환해 복합 명령이 실패하고 `set -e` 가 종료시킨다 | `if grep -q P f; then die; fi` |
| `cmd \| head -1` | cmd 가 계속 쓰는 동안 head 가 먼저 닫아 SIGPIPE(141). `pipefail` 이 이를 실패로 본다. 레이스라 간헐적이다 | 입력을 끝까지 읽는 `awk 'NR==1{...}'` |

## 테스트

`go test ./...` 하나로 전부 돌린다. 테스트는 모킹하지 않고 **실제 파일시스템·SQLite** 를
쓴다 — 이 도구의 버그는 파일 권한·원자적 쓰기·트랜잭션 경계에서 나오고 그건 모킹하면
보이지 않는다.

**외부 도구 교차 검증**이 핵심이다. 우리가 만든 것을 우리 코드로만 검증하면 서로의 버그를
가려 준다. 외부 도구가 없으면 해당 테스트만 skip 된다.

| 도구 | 확인하는 것 |
|---|---|
| `openssl verify` | 발급한 인증서가 Root 로 검증되고, **다른 CA 로는 실패한다**(음성 통제) |
| `openssl verify -crl_check` | 폐기한 인증서를 **거부**하고 폐기하지 않은 것은 통과시킨다 |
| `openssl x509 -text` | SAN·확장·KU/EKU·SKI/AKI 가 실제로 DER 에 들어갔다 |
| `openssl req -verify` | 우리가 만든 CSR 의 자기서명이 유효하다 |
| `openssl pkcs12 -info` | p12 가 AES-256-CBC 다(`Modern2023` 고정이 깨지지 않았다) |
| `keytool -list` | **Java 자신이** 우리가 쓴 JKS·p12 를 읽는다(keytool 의존 제거의 증거) |
| `kubectl apply --dry-run=client` | 생성한 Secret·Ingress 가 실제 스키마를 통과한다 |
| `nginx -t` | 생성한 nginx 설정에 문법 오류가 없다 |

그 외 회귀 테스트:

- **동시 발급** 8건에 serial·순번 중복 0 (순번 할당이 `BEGIN IMMEDIATE` 밖으로 새면 잡힌다)
- **보상 삭제** — 번들 쓰기를 실패시켜 DB 행이 남지 않는지 본다. 해당 코드를 제거하면
  테스트가 실패하는 것으로 실효성을 확인했다
- **경로 탈출** — zip·tar 양쪽에서 `../x`, `../../x`, `a/../../x`, `/etc/passwd` 를 막는지
- **FlagSet 충돌** — 모든 하위 명령의 플래그를 실제로 등록해 본다(중복은 런타임 panic 이다)
- **TUI** — Bubble Tea 모델을 직접 구동해 키 입력을 흉내낸다. 메뉴 구조·저작권 줄·구분선·
  블록 문자 부재·드롭다운이 화살표로 열리지 않음·SAN 의 Enter 줄바꿈·한글 폭 2칸·
  화면 전환 후 입력 보존·**모든 화면이 터미널 폭과 높이를 넘지 않음**(80/100/140칸)
- **예시 설정 로드** — `deploy/config.example.toml` 이 실제로 파싱되는지. Go 는 모르는 키를
  거부하므로 예시가 스키마에서 벗어나면 복사한 사용자가 바로 오류를 만난다

실제 pty 로 TUI 를 띄워 눈으로 확인한 것은 테스트가 잡지 못한 문제를 드러냈다(긴 내용이
푸터를 밀어내는 것, 모달 테두리가 접히는 것). 그 뒤 두 문제를 잡는 테스트를 추가했다.
