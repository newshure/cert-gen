# TUI 흐름

`cert-gen tui`. Bubble Tea(Elm 구조) 로 만들었다.

**TUI 는 편의 계층이고 CLI 가 정본이다.** 그래서 각 화면은 작업이 끝나면 '같은 일을 하는
CLI 명령' 을 함께 보여 준다 — TUI 로 익힌 절차를 스크립트로 옮길 수 있어야 하고, 무엇이
실행되었는지도 그래야 분명해진다.

---

## 화면 구성

```
┌────────────────────────┬──────────────────────────────────────────────────┐
│ cert-gen               │ 인증서 발급                     ← 화면 제목      │
│                        │                                                  │
│  0. 개인키 생성·관리   │  CA 선택 방식                                    │
│  1. rootCA 생성        │  ┌────────────────────────────────────────────┐  │
│  2. 인증서 발급        │  │ ① 발급 이력에서 고르기                  ▾ │  │
│  3. 인증서 변환        │  └────────────────────────────────────────────┘  │
│  4. 발급 이력·만료 조회│    스페이스로 목록 열기                          │
│  5. 서버에 CA 신뢰 등록│  …                                               │
│  6. 백업 · 복원        │                                                  │
│                        │  ┌───────────┐                                   │
│  CA 를 골라 서버·      │  │  발급 (I) │          ← 버튼에 단축키 표시     │
│  클라이언트 인증서를   │  └───────────┘                                   │
│  발급한다              │                                                  │
│        ↑ 선택 항목 설명│                                                  │
└────────────────────────┴──────────────────────────────────────────────────┘
 발급 완료: #1 web.hd.local                        ← 상태 한 줄
 Tab/↑↓ 이동   Enter 다음·실행   Esc 메뉴   Alt+0~6 바로가기   …
 저작권자: HaeDong   출처: https://theknowledges.net   사용조건: 출처 명시 시 자유 사용
```

### 지키는 규칙

| 규칙 | 왜 |
|---|---|
| 좌측 메뉴 / `│` 구분선 / 우측 콘텐츠 | 어디가 메뉴이고 어디가 내용인지 선으로 분명히 한다 |
| 선택 항목에 **배경색** | 글자색만 바꾸면 좁은 터미널·단색 테마에서 구분이 안 된다. 항목 **폭 전체**를 칠한다(글자 길이만 칠하면 들쭉날쭉하다) |
| 포커스가 콘텐츠로 가도 현재 화면은 계속 표시 | 지금 어느 화면인지 잃지 않는다 |
| 저작권 줄은 **모든 화면**에 | 사용 조건이므로 특정 화면에만 있으면 안 된다 |
| 반칸 블록 글리프(`▔▁▊▎█`) 금지 | 폰트에 따라 `ㅁ` 로 깨지고, 깨지지 않아도 화면이 어지러워진다. 가는 선(`─│┌`)만 쓰고 강조는 배경색으로 한다 |
| 동아시아 문자는 2칸으로 센다 | 한글 CN 이 섞인 표의 열이 어긋난다 |
| 어떤 줄도 터미널 폭·높이를 넘지 않는다 | 넘치면 줄이 접혀 레이아웃 전체가 깨진다. 80/100/140칸으로 테스트한다 |

## 메뉴와 흐름

번호를 고정한다. 순서를 바꾸면 손에 익은 번호가 달라지므로, 항목을 추가해도 기존 번호는
유지한다. 각 메뉴의 단계별 흐름은 `docs/blueprint/menu-flows.md` 에 있다.

| 번호 | 화면 | 핵심 |
|---|---|---|
| 0 | 개인키 생성·관리 | 목록(`쌍` 열) · 새 키(`n`) · 삭제(`d`). 쓰이는 키는 삭제를 거부한다 |
| 1 | rootCA 생성 | DN 폼 + 키 선택(새로 생성 / 0번에서 만든 키) |
| 2 | 인증서 발급 | **CA 선택 ① 이력 / ② 디렉터리** → DN · SAN · 프로필 · 키 |
| 3 | 인증서 변환 | **대상 ① 이력 / ② 외부 파일** → 포맷(p12·JKS·DER·PEM·K8s·신뢰저장소) |
| 4 | 발급 이력·만료 조회 | 목록 → 상세 → 검증(`v`) · 갱신(`r`) · 폐기(`x`) · 사유 변경(`s`) |
| 5 | 서버에 CA 신뢰 등록 | CA·대상 선택 → **등록 명령 생성**(실행하지 않는다) |
| 6 | 백업 · 복원 | 동작 선택(① 생성 / ② 복원) → 복원은 드라이런 후 `y` 확인 |

시작 화면은 **4번(발급 이력)** 이다. 실사용 빈도가 발급보다 "지금 뭐가 있고 언제 만료되나"
가 높고, 처음 열었을 때 상태를 보여 주는 편이 자연스럽다.

### 분기를 명시적으로 둔다

2·3·6번은 모두 "동작/대상을 먼저 고르는" 형태다. 암묵적 분기("경로가 비면 A, 있으면 B")를
쓰지 않는다 — 되돌릴 수 없는 동작(복원)을 실수로 고르게 만든다.

## 입력 위젯

기성 위젯을 쓰지 않고 직접 만든 것이 둘 있다. 이유가 분명하다.

### 드롭다운 — **스페이스로만** 열린다

```
닫힘:  [ 서버 (serverAuth)  ▾ ]    ← ↑↓ 는 폼의 다음·이전 항목으로 간다
스페이스 → 열림:
       [ 서버 (serverAuth)  ▴ ]
       ┌──────────────────────┐
       │   서버 (serverAuth)  │    ← ↑↓ 가 여기서만 커서를 움직인다
       │   클라이언트         │
       │   서버+클라이언트    │
       └──────────────────────┘
       Enter 확정 / Esc 취소(값 유지)
```

화살표로 열리면 항목 사이를 지나다니기만 해도 값이 바뀌어, 의도하지 않은 설정으로 발급하게
된다. Enter 로도 열지 않는다 — 폼에서 Enter 는 '다음·실행' 이고, 가로채면 제출이 막힌다.

### SAN 입력 — **Enter 가 줄바꿈**

```
SAN (한 줄에 하나)
┌──────────────────────────────────┐
│ dns:api.hd.local                 │
│ ip:10.0.0.5▏                     │
│                                  │
└──────────────────────────────────┘
  접두어를 생략하면 자동 판별합니다. CN 은 자동 포함됩니다
```

한 줄 입력은 Enter 를 '제출' 로 먹어 줄바꿈이 되지 않는다. 폼 이동은 **Tab** 이다.
빈 줄은 걸러서 넘긴다(빈 SAN 이 넘어가면 검증에서 엉뚱한 오류가 난다).

## 모달

패스프레이즈 입력에만 쓴다. 암호화된 CA 키로 갱신·폐기·CRL 생성을 하려면 필요하다.

```
┌───────────────────────────────────────────────┐
│ CA 패스프레이즈 — 갱신                        │
│ CA "hd-root-ca" 의 개인키가 암호화되어        │
│ 있습니다. 갱신에는 CA 서명이 필요합니다.      │
│                                               │
│ ┌───────────────────────────────────────────┐ │
│ │ *********                                 │ │
│ └───────────────────────────────────────────┘ │
│                                               │
│ Enter 확인   Esc 취소(C)                      │
└───────────────────────────────────────────────┘
```

- 입력은 **마스킹**한다(어깨너머로 읽히지 않게).
- 모달은 **앱 셸이** 들고 있고, 떠 있는 동안 전역 키조차 가로채지 않는다. 화면마다 구현하면
  어떤 화면에서는 모달 위로 단축키가 새어 나간다.
- **Ctrl+C 만 예외**다. 어떤 상태에서도 빠져나올 길은 있어야 한다.
- Esc 는 작업을 **하지 않고** 닫는다. 빈 패스프레이즈로 시도하면 엉뚱한 오류가 난다.
- 콘텐츠 영역을 대체해 그린다. 레이아웃 바깥에 그리면 저작권 줄이 밀린다.

## 키맵

| 키 | 동작 |
|---|---|
| `↑` `↓` / `k` `j` | 항목 이동 |
| `Enter` | 메뉴에서 열기 / 폼에서 다음·실행 / 목록에서 상세 |
| `Tab` `Shift+Tab` | 폼 항목 이동 |
| `0`~`6` | 메뉴 바로가기 — **글자 입력을 받지 않을 때만** |
| `Alt+0`~`Alt+6` | 메뉴 바로가기 — **어디서든** |
| `스페이스` | 드롭다운 열기 |
| `Esc` | 콘텐츠 → 메뉴 / 상세 → 목록 / 모달 취소 |
| `PgUp` `PgDn` | 콘텐츠 스크롤 |
| `F5` `Ctrl+R` | 새로고침 |
| `q` (메뉴에서) · `Ctrl+C` | 종료 |

**숫자키가 상황에 따라 다르게 동작하는 이유**: 텍스트 필드에 포커스가 있으면 숫자는 글자여야
한다(CN 에 숫자를 넣을 수 없으면 안 된다). 그래서 맨 숫자는 목록·드롭다운처럼 글자를 받지
않는 상태에서만 바로가기로 쓰고, 어디서든 되는 길로 `Alt+숫자` 를 둔다.

화면별 추가 키는 하단에 표시된다. 폭이 부족하면 뒤쪽(전역 키)부터 버리고 `…` 로 알린다.

## 넘치는 내용

lipgloss 의 `Height()` 는 채우기만 하고 **자르지 않는다.** 그대로 두면 긴 내용이 흘러
푸터와 저작권 줄을 밀어낸다. 그래서 앱 셸이 콘텐츠를 자르고 알린다.

```
  … 30/68줄  PgUp/PgDn 으로 넘깁니다
```

조용히 자르면 사용자는 내용이 없다고 믿는다. 작업이 성공하면 콘텐츠를 **끝으로** 보낸다 —
방금 실행한 결과를 보려고 스크롤해야 하는 것은 잘못된 동작이다.

## 열화 경로

TTY 가 아니면 TUI 를 **거부하고** 같은 일을 하는 CLI 명령을 안내한다.

```
$ cert-gen tui < /dev/null
오류: 터미널이 아니어서 TUI 를 띄울 수 없습니다. CLI 를 쓰세요:
  cert-gen init
  cert-gen ca create --cn "<조직> Root CA"
  cert-gen cert issue --cn <호스트명>
  cert-gen cert list
```

터미널이 너무 작으면(72×18 미만) 억지로 그리지 않고 무엇을 하면 되는지 알린다.

## 테스트

Bubble Tea 모델을 **직접 구동**해 키 입력을 흉내낸다. `tea.Program` 을 띄우지 않으므로
`tea.Cmd` 를 테스트가 직접 실행해 결과를 반영한다(`drain`).

확인하는 것:

- 메뉴 구조(번호·라벨이 지정한 그대로), 저작권 줄, 구분선
- **블록 문자 부재** — 모든 화면에서 `▔▁▊▎█` 등이 나오지 않는지
- 드롭다운이 화살표·Enter 로 열리지 않고 스페이스로만 열리는지, Esc 가 값을 바꾸지 않는지
- SAN 의 Enter 줄바꿈, Tab 이 폼 이동으로 넘어가는지, 빈 줄이 걸러지는지
- 폭 계산(한글 2칸), `padDisplay` 가 정확히 폭을 채우는지
- **모든 화면·모달이 터미널 폭과 높이를 넘지 않는지**(80/100/140칸)
- 화면 전환 후 입력이 보존되는지
- 모달이 전역 키를 삼키고 Ctrl+C 만 통과시키는지, 입력이 마스킹되는지
- 키 생성 → CA 생성 → 발급 → 검증 → 갱신 → 폐기 → 백업 전 흐름

실제 pty 로 띄워 눈으로 본 것이 테스트가 잡지 못한 문제를 드러냈다(긴 내용이 푸터를
밀어내는 것, 모달 테두리가 접히는 것). 그 뒤 두 문제를 잡는 테스트를 추가했다.
`CERT_GEN_TUI_DUMP=1 go test ./internal/tui/ -run TestDump` 로 화면을 찍어 볼 수 있다.
